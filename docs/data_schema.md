# Data Schema

This document describes the data formats used throughout the Smart Wi-Fi Bandwidth Sharing project.

## 1. Provenance Labels

Every metric produced by the system is classified using one of five provenance labels defined in `backend/data_provenance.py`.

| Label | Description | Example Metrics |
|-------|-------------|-----------------|
| `REAL_DATASET` | Derived from the real packet-capture dataset | User activity, requested bandwidth from `Cleaned_Dataset.csv` |
| `REAL_RUNTIME_MEASUREMENT` | Measured from the running system at runtime | CPU usage, memory usage, actual network interface counters |
| `CALCULATED_FROM_REAL_DATA` | Computed from real inputs using a deterministic algorithm | Nash allocation, Jain Fairness Index, utilization percentages |
| `SIMULATION` | Generated by the research simulation engine for demonstration or experimental purposes | Synthetic user requests, simulated latency, synthetic experiment results |
| `USER_INPUT` | Provided directly by a human user via the UI | Manual bandwidth caps, QoS preference sliders |

### 1.1 How Provenance Is Used

- In the frontend, metrics are tagged with their provenance so users can distinguish between measured and simulated values.
- In the backend, the `allocation_service.py` and `evaluation_service.py` do not distinguish provenance internally; they operate on whatever user data is passed to them.
- In documentation and papers, results must clearly state whether they are `SIMULATION` or `CALCULATED_FROM_REAL_DATA`.

## 2. Raw Experiment Results

### 2.1 File: `data/experiment_results.csv`

This file contains one row per `(experiment, strategy)` pair.

#### Schema

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `experiment_id` | string | No | Unique identifier: `exp_{seed}_{number_of_users}` |
| `timestamp` | string (ISO 8601) | No | UTC timestamp of experiment execution |
| `seed` | integer | No | Random seed used for this experiment |
| `number_of_users` | integer | No | Number of simulated users in this run |
| `strategy` | string | No | Allocation strategy name |
| `total_bandwidth` | float | No | Total available bandwidth (Mbps) |
| `total_allocated` | float | No | Sum of all allocated bandwidths (Mbps) |
| `utilization_percentage` | float | No | (total_allocated / total_bandwidth) × 100 |
| `jain_fairness_index` | float | No | Jain's Fairness Index ∈ [0, 1] |
| `average_utility` | float | No | Mean utility across all users |
| `latency_ms` | float | No | Simulated latency in milliseconds |
| `jitter_ms` | float | No | Simulated jitter in milliseconds |
| `repetition` | integer | No | Repetition index (1 for single-seed runs) |

#### Allowed Values for `strategy`

| Strategy Name | Description |
|---------------|-------------|
| `Equal Allocation` | Equal share of capacity |
| `Proportional Allocation` | Proportional to requested bandwidth |
| `Priority Allocation` | QoS-priority weighted allocation |
| `Game Theory` | Nash equilibrium allocation |

#### Example Rows

```csv
experiment_id,timestamp,seed,number_of_users,strategy,total_bandwidth,total_allocated,utilization_percentage,jain_fairness_index,average_utility,latency_ms,jitter_ms,repetition
exp_42_5,2025-08-30T03:00:00,42,5,Equal Allocation,100.0,43.51,43.51,0.8536,0.8985,15.23,3.45,1
exp_42_5,2025-08-30T03:00:00,42,5,Proportional Allocation,100.0,43.51,43.51,0.8536,0.8985,15.23,3.45,1
exp_42_5,2025-08-30T03:00:00,42,5,Priority Allocation,100.0,43.51,43.51,0.8536,0.8985,15.23,3.45,1
exp_42_5,2025-08-30T03:00:00,42,5,Game Theory,100.0,28.5,28.5,0.8938,1.5674,15.23,3.45,1
```

#### Notes

- Latency and jitter are **global per experiment**, not per user or per strategy. The same values appear on all rows with the same `experiment_id`.
- `total_bandwidth` is currently always 100.0 Mbps in the default configuration, but the column is preserved for future experiments with variable capacity.

## 3. Aggregated Results

### 3.1 Multi-Seed Aggregates

When running multi-seed experiments (see `docs/reproducibility.md`), results are saved to `data/multi_seed_results.csv` with the same schema as `experiment_results.csv`, but with multiple `seed` values.

### 3.2 Ablation Study Aggregates

Ablation study files (e.g., `data/ablation_w_c.csv`) extend the schema with the varied parameter:

| Column | Type | Description |
|--------|------|-------------|
| `congestion_penalty` | float | Value of w_C used in this run |
| `number_of_users` | integer | User count |
| `strategy` | string | Strategy name |
| `total_allocated` | float | Total allocated bandwidth |
| `utilization_percentage` | float | Utilization percentage |
| `jain_fairness_index` | float | Jain's Fairness Index |
| `average_utility` | float | Average utility |

## 4. Real Dataset Schema

### 4.1 File: `data/Cleaned_Dataset.csv`

This is the raw real-world dataset. Its exact schema depends on the source capture. The project processes it into a normalized format.

### 4.2 File: `data/processed_users.csv`

The processed real dataset has the following schema:

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `user_id` | string | No | Unique user identifier |
| `activity` | string | No | Traffic class (e.g., `web`, `gaming`, `streaming`) |
| `requested_bandwidth` | float | No | Bandwidth demand (Mbps) |

#### Example Rows

```csv
user_id,activity,requested_bandwidth
user_001,web,0.0005
user_002,web,0.0015
user_003,gaming,0.0066
user_004,gaming,0.0063
user_005,streaming,0.0811
```

#### Notes

- The real dataset uses normalized bandwidth values (typically in the range 0.0001–0.1 Mbps), unlike the synthetic generator which produces values in the range 2–30 Mbps.
- When using real data, the total bandwidth should be scaled accordingly, or the requested values should be rescaled to Mbps.
- The `activity` values in the real dataset (`web`, `gaming`, `streaming`) map to the simulation activities as follows:
  - `web` → `browsing`
  - `gaming` → `gaming`
  - `streaming` → `streaming`
- Other activities in the real dataset (if any) fall back to the `default` activity weight of 1.0.

## 5. Experiment Configuration Schema

### 5.1 File: `backend/simulation/experiment_config.py`

This Python module defines the default experiment parameters. It is not a JSON file, but its structure is equivalent to:

```json
{
  "EXPERIMENT_SEED": 42,
  "TOTAL_BANDWIDTH_MBPS": 100.0,
  "USER_COUNTS": [5, 10, 20, 30, 50, 100, 200, 373],
  "SCENARIO": "medium",
  "REPETITIONS": 1,
  "CONGESTION_PENALTY": 0.5,
  "STEP_SIZE": 0.5,
  "MAX_ITERATIONS": 100,
  "LATENCY_RANGE_MS": [8.0, 22.0],
  "JITTER_RANGE_MS": [1.0, 6.0],
  "OUTPUT_DIRECTORY": "data",
  "OUTPUT_FILE": "data/experiment_results.csv",
  "DATASET_PATH": "data/processed_users.csv",
  "EXPERIMENT_DESCRIPTION": "Scalability experiment comparing Equal, Proportional, Priority, and Game Theory allocation strategies across increasing user counts.",
  "VERSION": "1.0.0"
}
```

### 5.2 Runtime Configuration via JSON

The `experiment_runner.py` module also supports runtime configuration via a dictionary:

```python
EXPERIMENT_CONFIG = {
    "user_counts": [5, 10, 20, 30, 50, 100, 200, 373],
    "total_bandwidth": 100.0,
    "seed": 42,
    "scenario": "medium",
    "repetitions": 1,
    "output_directory": "data",
    "output_file": "data/experiment_results.csv",
    "description": "Scalability experiment comparing allocation strategies",
}
```

You can update this at runtime:

```python
from backend.simulation.experiment_runner import set_experiment_config

set_experiment_config(
    user_counts=[10, 20, 50],
    seed=123,
    total_bandwidth=200.0,
)
```

## 6. Simulation User Schema

### 6.1 In-Memory Representation

Synthetic users generated by `backend/simulation/user_generator.py` have the following structure:

```python
{
    "user_id": int,              # 1, 2, 3, ...
    "activity": str,             # One of ACTIVITIES
    "requested_bandwidth": float, # Mbps, rounded to 2 decimal places
    "activity_weight": float     # From ACTIVITY_CONFIG
}
```

### 6.2 Activity Configuration

```python
ACTIVITY_CONFIG = {
    "browsing": {
        "min_bandwidth": 2,
        "max_bandwidth": 10,

        "min_bandwidth": 10,

```

## 7. Traffic Scenario Schema

### 7.1 File: Generated by `generate_traffic_scenario()`

```python
{
    "scenario": str,                    # "low", "medium", "high", "extreme", or custom label
    "description": str,                 # Human-readable description
    "total_bandwidth": float,           # Total available bandwidth (Mbps)
    "number_of_users": int,             # Number of users in the scenario
    "total_requested_bandwidth": float, # Σ r_i
    "demand_ratio": float,              # total_requested / total_bandwidth
    "congestion_level": str,            # "LOW", "MODERATE", "HIGH", "EXTREME"
    "users": list[dict]                 # List of user dicts (see Section 6)
}
```

### 7.2 Congestion Level Thresholds

| Demand Ratio | Congestion Level |
|--------------|------------------|
| < 0.50 | LOW |
| < 1.00 | MODERATE |
| < 1.50 | HIGH |
| ≥ 1.50 | EXTREME |

## 8. Game Theory Allocation Result Schema

### 8.1 Return Value of `allocate_bandwidth()`

```python
{
    "total_bandwidth": float,               # Rounded to 2 decimals
    "total_requested_bandwidth": float,     # Rounded to 2 decimals
    "total_allocated_bandwidth": float,     # Rounded to 2 decimals
    "unused_bandwidth": float,              # max(0, total - allocated), rounded
    "utilization_percentage": float,        # Rounded to 2 decimals
    "jain_fairness_index": float,           # Rounded to 4 decimals
    "fairness_status": str,                 # "Excellent", "Good", "Moderate", "Poor"
    "iterations": int,                      # Number of Nash iterations used
    "users": list[dict]                     # Per-user results
}
```

### 8.2 Per-User Result Dict

```python
{
    "user_id": str,
    "activity": str,
    "requested_bandwidth": float,   # Rounded to 2 decimals
    "allocated_bandwidth": float,   # Rounded to 2 decimals
    "utility": float,               # Rounded to 4 decimals
    "activity_weight": float
}
```

## 9. Evaluation Result Schema

### 9.1 Return Value of `evaluate_all_strategies()`

A list of four dictionaries, one per strategy:

```python
[
    {
        "strategy": "Equal Allocation",
        "allocations": {user_id: float, ...},
        "metrics": {
            "total_allocated": float,
            "utilization": float,
            "fairness": float,
            "average_utility": float
        }
    },
    {
        "strategy": "Proportional Allocation",
        ...
    },
    {
        "strategy": "Priority Allocation",
        ...
    },
    {
        "strategy": "Game Theory",
        ...
    }
]
```

### 9.2 Metrics Sub-Schema

| Metric Key | Type | Unit | Description |
|------------|------|------|-------------|
| `total_allocated` | float | Mbps | Sum of all allocations |
| `utilization` | float | percent | Percentage of total capacity used |
| `fairness` | float | unitless | Jain's Fairness Index |
| `average_utility` | float | unitless | Mean utility across users |

## 10. How to Import Real WiFi Data

### 10.1 Required Format

Real Wi-Fi data should be formatted as a CSV with at least the following columns:

```csv
user_id,activity,requested_bandwidth
user_001,web,0.0005
user_002,gaming,0.0066
user_003,streaming,0.0182
```

### 10.2 Activity Mapping

Map your activity labels to the project's activity classes:

| Source Label | Project Activity | Notes |
|--------------|------------------|-------|
| `web`, `browsing`, `http` | `browsing` | Low latency/jitter sensitivity |
| `video_call`, `meeting`, `class` | `online_class` | High latency sensitivity |
| `game`, `multiplayer` | `gaming` | Highest latency and jitter sensitivity |
| `video`, `youtube`, `netflix` | `streaming` | Medium sensitivity |
| `download`, `ftp`, `backup` | `downloading` | Low sensitivity |
| Unknown | `browsing` | Falls back to default weight 1.0 |

### 10.3 Bandwidth Scaling

If your dataset uses units other than Mbps:

```python
# Example: convert Kbps to Mbps
df["requested_bandwidth_mbps"] = df["requested_bandwidth_kbps"] / 1000.0

# Example: scale to match total capacity
total_real = df["requested_bandwidth"].sum()
target_total = 100.0  # Mbps
df["requested_bandwidth"] = df["requested_bandwidth"] * (target_total / total_real)
```

### 10.4 Loading into the Experiment Runner

Place the processed file at `data/processed_users.csv` or specify a custom path:

```python
from backend.services.dataset_service import load_processed_dataset

users = load_processed_dataset("data/processed_users.csv")
```

Then pass the loaded users to the evaluation service:

```python
from backend.services.evaluation_service import evaluate_all_strategies

results = evaluate_all_strategies(
    users=users,
    total_bandwidth=100.0,
    latency=15.0,
    jitter=3.0
)
```
